# Документация по тестированию бота House Tenerife

Документ для QA и разработчиков: **что уже ломалось**, **как проверять**, **какой результат считать успехом**.  
Вести регрессию по этому чеклисту перед каждым деплоем и после правок языка / каталога / фото / handoff.

---

## 1. Быстрый старт

### Автотесты (без WhatsApp)

```bash
# Языки: все SUPPORTED_DETECT + путаницы ES↔FR, DE↔ES, ES↔PL, sticky
npm run test:languages

# Офлайн-пайплайн: язык, ссылки, off-topic, LID, модель
npm run test:stress:offline

# Детерминированные QA-фиксы (районы, бюджет, дубли ссылок, история…)
npm run test:fixes

# Ручные сценарии R1–R11 (только печать диалогов)
node scripts/test-fixes-dialogs.js --manual
```

**Перед деплоем минимум:** `test:languages` + `test:stress:offline` + `test:fixes` — все PASS.

### Живой WhatsApp

1. Новый чат или `/start` (сброс sticky-языка и контекста).
2. Писать **на языке теста** всю сессию (короткие «ok/да» не должны переключать язык).
3. Смотреть: ответ бота, Telegram-алерты, панель `/admin`, WhatsApp главному менеджеру.

### Ключевые env

| Переменная | Зачем |
|---|---|
| `AI_API_KEY` / `AI_MODEL` | Ответы и выжимки (`openai/gpt-4.1`) |
| `MANAGER_WHATSAPP` | Куда слать отчёт по диалогу |
| `MANAGER_DIALOG_REPORTS` | `1` вкл / `0` выкл отчёты |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` | Алерты / копии отчётов |
| `CONVERSATION_RUNTIME_LIMIT` | Сколько реплик поднимать из SQLite после деплоя (по умолчанию 80) |
| `SQLITE_PATH` / `SESSION_PATH` | Персистентность истории |

## 2. Языки

### Поддержка

| Код | Ответ бота (sales pack) | Детект |
|---|---|---|
| `ru` | да | да |
| `en` | да | да |
| `es` | да | да |
| `de` | да | да |
| `fr` | да | да |
| `pl` | да | да |
| `nl` | да | да |
| `uk` | → как `ru` | да |
| `pt`, `it`, `tr` | нет отдельного pack | детект есть |

Sticky-язык чата: короткие `ok` / `да` / `.` / «350k» / топонимы **не** переключают язык.

### Известные баги (регрессия обязательна)

| # | Симптом | Причина | Ожидание |
|---|---|---|---|
| L1 | Испанский → «Французский» | `é` в `pasé`/`hablé` попадало в FR-алфавит | `es` |
| L2 | ES + ссылка `Parking à vendre` → FR | французский slug/title в URL | `es`, шум вырезан |
| L3 | Немецкий → ES | `ü` в `für`/`würde` | `de` |
| L4 | ES `inversión` → PL | общая буква `ó` | `es` |
| L5 | `Puerto de la Cruz` → ES | топоним со стоп-словами | нейтрально / не менять sticky |
| L6 | Только URL `/es/property/…` → ES | path каталога | не задаёт язык клиента |
| L7 | FR `intéressé` → ES | любое слово на `-é` считалось ES | `fr` |
| L8 | NL `geïnteresseerd` → FR | буква `ï` | `nl` |
| L9 | После деплоя «забыл» язык диалога | история только в RAM | sticky + SQLite гидратация |

### Чеклист ручного теста языка

Для каждого языка **ru / en / es / de / fr / pl / nl**:

1. Приветствие + запрос объекта + бюджет → ответ **на том же языке**.
2. Серия коротких реплик (`ok`, `да`, `350k`) → язык **не прыгает**.
3. Ссылка на объект с `/es/` или `à vendre` в названии → язык = язык фразы клиента, не slug.

**Спец-тред ES (из продакшена):**

```
Buenos días podemos hablar por aquí ?
.
Yo lo del parking
Alquilarlo yo ya te pasé mi propuesta
Hola, estoy interesado/a en [Parking à vendre 317] https://housetenerife.eu/es/property/…
Por este te hablé yo que me hablastes
Y me dijistes esto
Yo ya te dije mi propuesta
```

Ожидание: во всех уведомлениях / ответах — **испанский**, не французский.

**Авто:** `npm run test:languages` → 64 PASS.

## 3. Ссылки на объекты (housetenerife.eu)

### Проблемы, которые были

| # | Симптом | Ожидание |
|---|---|---|
| U1 | Бот «не видит» ссылку клиента | Описание объекта из каталога/live-fetch, не отписка |
| U2 | Выдуманные / битые URL | Только реальные ссылки каталога |
| U3 | Дубли одной и той же ссылки | Без повторов в одном ответе |
| U4 | Не тот тип (просил апартаменты — дал виллу) | Тип совпадает с запросом |
| U5 | Не тот район (Adeje → Galeón и т.п.) | Район/макрорегион совпадает |
| U6 | Idealista / чужие домены | Не предлагать |
| U7 | Path `/es/` в URL меняет язык ответа | Язык = язык клиента |

### Чеклист

1. Клиент присылает ссылку `https://housetenerife.eu/…/property/…`  
   → бот кратко описывает объект (цена, тип, зона) + 1 уточняющий вопрос.
2. Клиент: «покажи варианты Adeje, апартаменты, 350k»  
   → 2–5 ссылок, цены в коридоре бюджета, тип = апартаменты.
3. Клиент меняет бюджет / регион (Тенерифе → Ибица)  
   → новый поиск, без старых ссылок «вслепую».
4. Нет объектов в коридоре  
   → честный fallback (ближайшие / «мало в бюджете»), без фантазии.

**Авто:** `test:fixes` (блоки ссылок, районов, типов) + `test:stress:offline` (extract/prompt).

## 5. История диалога и деплой

### Проблемы

| # | Симптом | Ожидание |
|---|---|---|
| H1 | После деплоя бот «не помнит» диалог | История из SQLite (до ~500), в RAM поднимается ~80 |
| H2 | Отчёт менеджеру только по хвосту после рестарта | Анализ по **полной** истории из БД |
| H3 | Менеджер пишет в чат — бот продолжает отвечать | AI отключается для чата (`setAiDisabled`) |

### Чеклист

1. Диалог 10+ реплик → рестарт процесса → следующая реплика клиента с контекстом.
2. В логе: `История … восстановлена: N сообщений`.
3. В `/admin` чат показывает полную переписку user/assistant/manager.

## 6. Отчёт главному менеджеру

Триггеры:

- клиент указал интерес к объекту (ссылка / «мне нравится» / выбор варианта);
- согласие на созвон / handoff.

Куда:

- WhatsApp на `MANAGER_WHATSAPP` (Максим);
- копия в Telegram-алерты;
- запись в панели handoff / purchase-requests.

Содержание отчёта:

- контакт + язык;
- объекты интереса;
- выжимка: о чём говорили, критерии, к чему пришли, что важно перед звонком.

Антиспам: повтор не чаще ~2 ч, кроме нового объекта / handoff (`force`).

### Чеклист

| # | Действие | Ожидание |
|---|---|---|
| M1 | ES-клиент прислал ссылку + «me interesa» | Отчёт на WhatsApp менеджера + Telegram |
| M2 | Тот же чат пишет ещё раз без нового объекта | Повторного отчёта нет (cooldown) |
| M3 | Новый объект в интересе | Новый отчёт |
| M4 | Клиент согласился на созвон | Отчёт / handoff с полной выжимкой |
| M5 | `MANAGER_DIALOG_REPORTS=0` | Отчёты не шлются |

**Проблема Максима (мотивация):** клиент уже прошёл вопросы с ботом, менеджер без контекста теряет доверие. Отчёт обязателен до/при передаче.

## 8. Воронка покупки / handoff

Стадии (упрощённо): интерес к объекту → деньги на руках / ипотека → документы → созвон.

| # | Действие | Ожидание |
|---|---|---|
| F1 | Выбрал объект | Заявка в `purchase-requests` + отчёт менеджеру |
| F2 | Согласие на звонок | `call_requested` / handoff, AI-выжимка |
| F3 | Отказ от звонка | Диалог продолжается, без эскалации |
| F4 | «Свяжите с менеджером» | Мягкое предложение → имя → передача |
| F5 | Менеджер отвечает из админки | Сообщение уходит клиенту, бот молчит |

## 9. Off-topic и качество ответа

| # | Действие | Ожидание |
|---|---|---|
| O1 | «Привет, как дела?» | Коротко + возврат к недвижимости |
| O2 | Погода / политика / шутки | Не уходит в длинный оффтоп |
| O3 | Путаница цели (жизнь vs инвестиция) | Уточняет один раз, дальше держит профиль |
| O4 | Обещание «подождите несколько минут / пришлю позже» без выдачи | Не должно быть «пустых обещаний» каталога |

## 14. Критерии «можно деплоить»

1. Все три автосьюта зелёные.
2. ES-тред с `pasé` / `à vendre` не уходит в FR.
3. Отчёт менеджеру уходит на `MANAGER_WHATSAPP` при интересе к объекту.
4. После рестарта бот поднимает историю из SQLite.
5. Ссылки только с каталога, без дублей и чужих доменов.
6. Нет регрессии DE↔ES и PL↔ES на канонических фразах.
